どちらがよいか比べるためには、同じ行と同じ指標が必要です。比較用の単回帰は変更しません。今回は評価対象を切り替えるのではなく、変更対象モデルの説明変数を増やします。

二つの入力から一つの予測

二つの説明変数から電力量を予測します。切片と二つの係数は、訓練60行から同時に学習します。単回帰の係数に別に計算した処理量の係数を足す方法ではありません。

もう一方を一定にする

この図では稼働時間を5時間に固定しています。処理量を40個増やすと、予測値の増分は処理量係数の40倍になります。点は説明用入力の予測であり、実測の点ではありません。

式と係数の単位

予測 = 切片 ＋ 時間係数×時間 ＋ 処理量係数×個数

  • 切片：kWh。
  • 時間係数：kWh/時間。処理量を一定にする。
  • 処理量係数：kWh/個。時間を一定にする。
各項を掛けた結果はすべてキロワット時になります。時間係数は処理量を一定にした変化です。切片は両方ゼロの式の値ですが、このデータから実設備の待機電力量だと断定することはできません。

Python：列名のリスト

candidate_features = [
    "operating_hours", "throughput_units"
]
X = train[candidate_features]

60行×2列の表を学習へ渡す。本文§4。

列名のリストに二つの名前を入れます。このリストで表から列を選ぶと、60行2列の入力になります。一列のときも二次元の表です。列名の順番を係数の順番と対応づけてください。

Python：学習と予測

candidate_model = LinearRegression()
candidate_model.fit(
    train[candidate_features], train["energy_kwh"]
)
pred = candidate_model.predict(

フィットは訓練表と実測値で学習します。予測には評価対象の表を渡します。学習と予測の両方で同じ列名リストを使うので、列の指定が一貫します。

Python：係数を列名と対応づける

print(candidate_model.intercept_)
print(candidate_features)
print(candidate_model.coef_.tolist())

係数配列は学習時の列順。途中で丸めない。

切片と係数を表示します。係数の配列だけを見るのではなく、直前の列名リストと対応させます。トゥーリストは配列を通常の数値リストへ変換します。手計算には丸める前の値を使いましょう。

R：式の右辺へ一項追加

candidate_formula <-
  energy_kwh ~ operating_hours + throughput_units
candidate_model <- lm(
  candidate_formula, data = train
)

式の+は説明変数の追加。本文§5。

式の左側は目的変数、右側は説明変数です。プラスは二つの説明変数を別の項として使う指定です。二つの数値列を足して一列にする意味ではありません。アスタリスクは交互作用も加えるので今回は使いません。

R：名前付き係数と予測

print(coef(candidate_model))
pred <- predict(
  candidate_model, newdata = evaluation
)

係数の名前を読む。newdataを省略しない。

コエフは名前付きの係数ベクトルを返します。インターセプトが切片です。予測には検証の表を明示します。ニューデータを省略して訓練行の予測を比較しないように注意しましょう。

同じ行のMAE・RMSE

  • 残差 = 実測 − 予測。
  • MAE：絶対値 → 平均。
  • RMSE：二乗 → 平均 → 平方根。
  • 訓練60行、検証20行を別々に比較。

どちらの指標もkWh。第10回§4を復習。

指標の定義は第10回と同じです。単回帰と重回帰で同じ行を使います。訓練の単回帰と検証の重回帰を比べても、説明変数を増やした効果だけの比較にはなりません。

  • residuals.png：二モデルの残差を横並びに。

シーエスブイは元の五列に両モデルの三種類の結果を追加した十一列です。主言語で保存します。比較用の値はメモか別名コピーで残してください。保存できたことだけでは課題完成とはいえません。

Pythonで変更する場所

# 変更前
candidate_features = ["operating_hours"]
# 変更後
candidate_features = [
    "operating_hours", "throughput_units"
]

比較用単回帰・評価対象は変更しない。

変更するのは候補の説明変数リストです。処理量という列名を追加します。フィットや予測の別の箇所へ違うリストを書き足さず、この共通の指定を使います。比較用の単回帰は残してください。

Rで変更する場所

# 変更前
candidate_formula <- energy_kwh ~ operating_hours
# 変更後
candidate_formula <-
  energy_kwh ~ operating_hours + throughput_units

学習行・目的変数を保つ。

アールでは候補の式へ処理量を加えます。プラスで一項追加するだけです。データを検証行へ変更したり、目的変数を説明変数へ混ぜたりしないように確認しましょう。

E005を手計算する

  • 稼働時間：4.8時間。処理量：116個。
  • 実測：37.42 kWh。
  • 予測：切片＋時間係数×4.8＋処理量係数×116。
  • 実測−予測の残差も確認する。

途中で係数を丸めない。

指定行の一つを、表示した係数で手計算します。二つの係数を違う列へ掛けていないか確認しましょう。行全体を見て計算することで、列の順序や予測の行ずれにも気づけます。

項目 概数

独立計算で得た概数です。手元の表示は丸める前の値で確認してください。時間係数は単回帰の係数と少し異なります。処理量も同時に含めて学習したため、条件付きの関係を表す係数になっています。

モデル MAE RMSE

単位はkWh。この20行では両指標が小さい。

訓練と検証を分けて読む

訓練と検証をそれぞれ比較すると、この例ではどちらも重回帰のアールエムエスイーが小さくなっています。ただし、訓練への当てはまりだけで将来の精度は決まりません。検証を繰り返し見ている点も覚えておきましょう。

5時間を固定して予測を比べる

  • 40個：約28.197306 kWh。
  • 80個：約32.962926 kWh。
  • 差：約4.765620 kWh = 処理量係数×40。

実測はない。誤差は計算しない。

主例の最後にある入力の変更を確認します。時間を同じにすることで、処理量係数だけで予測差を説明できます。実測値のない説明用入力なので、精度を確認できたことにはなりません。この実演を提出用コードへ追加する必要はありません。

比較と解釈の限界

  • 変数追加が検証性能を必ず改善するとは限らない。
  • 係数の数値だけで重要度を順位付けしない。
  • 条件付きの予測関係を因果効果と断定しない。
  • 各列が範囲内でも、組合せの精度は未保証。
係数の単位が違うと、数値の大小をそのまま重要さに置き換えることはできません。また、モデルの予測関係と因果効果は別です。訓練範囲に入る値を組み合わせただけで精度が保証されるわけでもありません。
