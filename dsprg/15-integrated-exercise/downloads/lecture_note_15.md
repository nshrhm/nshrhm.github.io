## 3. A：単回帰と重回帰を比較する

### 条件を固定する

設備CSVは第8〜12回の80行と同じです。`split == "train"` の60行だけで学習し、`split == "validation"` の20行で比較します。目的変数は `energy_kwh`（kWh）。比較用単回帰の説明変数は `operating_hours`（時間）です。変更対象に `throughput_units`（個）を追加します。ID・分割列はモデルに入れません。最終確認20行は今回使いません。

Pythonでは `candidate_features` のリストを変更します。

```python
candidate_features = ["operating_hours", "throughput_units"]
```

Rでは学習へ渡す式を変更します。

```r
candidate_formula <- energy_kwh ~ operating_hours + throughput_units
```

主言語用と照合用の両方で同じ変更を行います。比較用単回帰、学習行、目的変数、検証行、指標の定義を変えないでください。

### 学習・表示を読む

| 操作 | 入力と目的 | 戻り値・読み方 |
|---|---|---|
| Python `LinearRegression().fit(X, y)` | 行×説明変数列の二次元Xと目的変数y。既定の切片あり最小二乗 | 学習済みモデル。`coef_` の並びはXの列順、`intercept_` は切片 |
| Python `predict(X)` | 同じ列を持つ予測対象のX | 各行の予測電力量。IDとの対応を保つ |
| R `lm(式, data=train)` | 式の右辺を説明変数、左辺を目的変数として訓練行で学習 | モデル。`coef(model)` は列名付き係数 |
| R `predict(model, newdata=...)` | 学習済みモデルと必要列を持つ新しい表 | 各行の予測値。ここでは検証行を渡す |

主言語は両モデルについて訓練と検証のID・件数・予測・残差・MAE・RMSEを表示します。照合言語は変更対象だけを元CSVから独立に学習し、訓練／検証IDと件数、係数、検証20行の結果と指標を表示します。相手のCSVを読むことは独立計算になりません。

残差＝実測値−予測値。負なら予測が実測値より大きいことを意味します。MAEは絶対残差の平均、RMSEは残差二乗の平均の平方根。分母は評価件数、単位はいずれもkWhです。Pythonの二乗は `** 2`、Rは `^2` です。

`figure.png` は両モデルの検証残差を並べ、共通縦軸・0線・時間とkWhの単位を付けます。残差の広がりと指標を合わせて読みます。処理量追加による検証誤差の減少を一般には保証できません。

### E005の手計算と係数の意味

十分な桁数の表示を使い、次を計算します。

`予測 = 切片 + operating_hoursの係数 × 4.8 + throughput_unitsの係数 × 116`

途中で丸めず、最後に表示だけ丸めます。コードのE005の予測・残差と照合し、途中式と結果を記録します。

時間の係数の単位はkWh/時間、処理量はkWh/個。重回帰の係数は、**もう一方を一定にしたときの予測値の変化**です。単位の違う係数の大きさだけで重要度を順位付けしません。観測上の関係は因果効果と断定できません。繰り返し確認してきた検証データの結果は、新規データの性能保証ではありません。

## 4. B：群数を変えて特徴を比較する

### 標準化・初期中心を固定する

iris150行の4測定値（がく片長・幅、花弁長・幅、いずれもcm）を使います。IDと種類を入力から除きます。全150行の各列から平均を引き、標本標準偏差（分母n−1）で割ります。Pythonの `X.std(ddof=1)` とRの `scale(X, center=TRUE, scale=TRUE)` はこの定義です。各値は無次元になります。

主言語・照合言語とも、指定箇所だけを変更します。

```python
k_candidate = 3
```

```r
k_candidate <- 3
```

比較用k=2を固定します。初期中心取得は完成済みで、標準化後のI001・I101（k=2）、I001・I051・I101（k=3）を使います。これらは共通の初期条件であり、種類を代表する正解中心ではありません。

| 操作 | 引数の目的 | 戻り値・読み方 |
|---|---|---|
| Python `KMeans(...).fit(Z)` | 4列の標準化表。`init` は共通初期中心、`n_init=1`、`algorithm="lloyd"`、`max_iter=300`、`tol=1e-10` | `labels_` は行ごとの所属、`cluster_centers_` は群×4列の中心、`inertia_` は群内平方和 |
| R `kmeans(Z, centers=..., nstart=1, algorithm="Lloyd", iter.max=300)` | 同じ標準化表と初期中心行列 | `cluster` は所属、`centers` は中心、`size` は件数、`tot.withinss` は群内平方和 |
| 群別平均 | 元のcm単位の4測定値を所属で集計 | 群の特徴を元の単位で説明するための表 |

群内平方和は各行とその所属中心との**4次元の二乗距離の合計**です。小さいだけで正しいkと判断せず、件数・群平均・分ける目的も考えます。種類の数が3であることをk=3の正解の根拠にはしません。クラスタ番号に大小・順位の意味はありません。

### 図と独立照合

主言語は標準化PCAを一度だけ計算し、同じPC1–PC2座標・範囲・縦横比を両パネルに使います。**群分けは4次元、図は2次元への投影**です。二次元で近く見えることだけで所属の誤りを判断できません。軸は無次元で、寄与率を併記します。

照合言語は変更対象k=3だけを元CSVから独立に計算します。PCA・図・ファイル保存は不要です。150行の所属、中心・件数・群平均・群内平方和を確認します。Pythonの0始まりとRの1始まりなど、番号が異なる場合は中心から一対一に対応を決め、全行・全集計で同じ対応を使います。行ごとに都合よく番号を付け替えてはいけません。

### I001の手計算

I001の標準化済み4値をz、各群中心をcとして、各中心まで `(z1−c1)^2 + … + (z4−c4)^2` を計算します。3つの二乗距離を比べ、最小の群とコードの所属が対応することを確認します。途中を丸めず、中心の4列の順にも注意します。

今回の全データ探索は、新しいデータに対する予測性能評価とは異なります。得られた群が唯一・大域的最適・種類の正解であるとは主張できません。

## 5. 保存・再読込・再実行を確かめる

保存先は `work/exercises/lesson15/output/A/` または `B/`。主言語だけが `analysis.csv` と `figure.png` を作ります。描画・保存・再読込の処理は完成済みです。

| 経路 | analysis.csvの列 |
|---|---|
| A（20行） | 元の `id,split,operating_hours,throughput_units,energy_kwh` と、`simple_`／`candidate_`それぞれの `prediction_kwh,residual_kwh,absolute_error_kwh`、計11列 |
| B（150行） | `id` と4測定値、`baseline_cluster,baseline_distance_sq,candidate_cluster,candidate_distance_sq`、計9列 |

| 保存・照合処理 | 目的・引数 | 結果の読み方 |
|---|---|---|
| Python `to_csv(path, index=False)` | 表を指定パスに保存。行番号を余分な列にしない | 戻り値は使わず、実ファイルを確認 |
| Python `read_csv(path, float_precision="round_trip")` | 保存したCSVを再読込し、浮動小数点の往復を保つ | 新しいDataFrameを返す |
| Python `astype("int64")`（Bの群番号） | 整数の型を統一して保存前後の型差を防ぐ | 同じ値で型を揃えたSeries |
| Python `equals(other)` | 保存前と再読込後の表の値・型を比較 | `True` が一致。`False` なら原因を調べる |
| R `write.csv(..., row.names=FALSE)`／`read.csv(...)` | BのCSV保存／読込。Aは既習の `write_csv`／`read_csv` | 再読込した表で確認 |
| R `all.equal(target,current,check.attributes=FALSE,tolerance=1e-8)` | 表をdata.frameに揃え、値の差を確認 | 一致なら `TRUE`、異なる場合は差の説明。文字列をTRUEと誤読しない |

保存の成功メッセージだけで終えず、指定フォルダーのCSVとPNGも開いて確認してください。両コードを先頭から再実行し、同じ結果になることと、今回の成果物であることを確かめます。実行途中の変数を使い回した結果は再現性の確認になりません。

## 6. レポートを書く

空の[経路Aひな形](templates/report_A.md)／[経路Bひな形](templates/report_B.md)、または同名DOCXを使えます。1〜2ページ程度が目安ですがページ数自体は評価しません。図を挿入しても読める大きさを保ちます。

1. **問いと条件**：問い、実行前の予想、入力行・列、主言語、変更箇所と固定条件。
2. **数値と図**：比較に必要な件数・係数／群平均・指標を単位付きで整理し、今回のfigure.pngを挿入。
3. **独立照合・手計算・再実行**：具体的な行と数値、他方の言語、再読込、再実行の結果。
4. **回答と限界**：数値・図に基づく回答、いえないこと。AI利用時は採用箇所と自分の確認方法。

「よくなった」「一致した」だけでは根拠が伝わりません。何を、どの行・数値・単位で比べたかを書きます。予想と違った結果も、その違いを確かめて説明すれば分析の記録になります。AI利用の有無そのものは加点・減点条件ではありません。
