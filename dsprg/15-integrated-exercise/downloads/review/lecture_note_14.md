## 2. 距離と尺度

列ごとに平均を引き、標本標準偏差で割ります。標準偏差の分母はn−1です。Pythonは`X.std(ddof=1)`、Rは`sapply(X, sd)`を使います。

`z = (測定値 − 列平均) / 標本標準偏差`

標準化後は無次元です。cmからmmへ一つの列だけ変えると、その列の差が10倍になり、二乗距離への寄与は100倍になります。標準化は列の尺度を揃える操作ですが、どの問いにも必ず最適という意味ではありません。

4次元の二乗距離は、対応する4つの値の差を二乗して足します。

`distance_sq = (z1-c1)^2 + (z2-c2)^2 + (z3-c3)^2 + (z4-c4)^2`

ユークリッド距離はこの平方根です。最も近い中心を比べるときは平方根を取っても順序が変わりません。Pythonの累乗は`**`、Rは`^`です。Pythonの`sum(axis=1)`とRの`rowSums()`は、各行の4項を足して行数分の値を返します。

## 3. k-meansの流れ

1. k個の初期中心を置く。
2. 各行を最も近い中心の群へ割り当てる。
3. 各群の平均へ中心を移す。
4. 所属が安定するまで繰り返す。

今回はLloyd法を使います。初期中心はk=2ならI001・I101、k=3ならI001・I051・I101の標準化済み4値です。取得部分は完成済みです。このIDは演習の初期条件であり、種類を代表する正解中心ではありません。種類列を参照して中心を選ぶコードにはしません。

初期中心が変わると異なる解へ収束することがあります。同じ乱数seedをPythonとRへ指定しても、同じ初期中心になるとは限りません。今回は中心そのものと更新方法を揃えて確認します。大域的な最適解を保証する設定ではありません。

## 4. Pythonの読み方

| 構文・関数 | 目的・主な引数 | 戻り値・結果の読み方 |
|---|---|---|
| `KMeans(...)` | `n_clusters`は群数、`init`はk×4の初期中心。`n_init=1`、`algorithm="lloyd"`、`max_iter=300`、`tol=1e-10` | 設定したモデル。まだ群分けはしていない |
| `model.fit(Z)` | 150×4の標準化表で群分けする | 学習したモデル自身。`species`は渡さない |
| `model.labels_` | 各行の所属を得る | 長さ150。通常0から始まる整数で、大小に意味はない |
| `model.cluster_centers_` | 各群の中心を得る | k×4の配列。列は入力の`features`と同じ順序、無次元 |
| `model.inertia_` | 群内平方和を得る | 所属中心までの二乗距離の合計。無次元 |
| `groupby("cluster")` | 所属で行をまとめる | グループ化した対象。`size()`は件数、`mean()`は列ごとの平均 |
| `to_string(float_format=...)` | 手計算用に十分な桁数で表示する | 表示用文字列。計算する数値自体は丸めない |

`X.assign(cluster=labels)`は元のcm単位の表へ所属を付けます。その群平均は、標準化空間の中心とは数値・単位が違います。`中心×標本標準偏差＋列平均`で元の単位へ戻した値と対応します。

## 5. Rの読み方

| 構文・関数 | 目的・主な引数 | 戻り値・結果の読み方 |
|---|---|---|
| `kmeans(Z, centers=initial, ...)` | 150×4の表とk×4の初期中心を渡す。`algorithm="Lloyd"`、`iter.max=300`、`nstart=1` | 群分けの結果を格納したリスト |
| `model$cluster` | 各行の所属 | 長さ150。通常1から始まる整数 |
| `model$centers` | 各群の中心 | k×4行列。列名と対応を確認する |
| `model$size` | 各群の件数 | 長さk。合計は150 |
| `model$tot.withinss` | 群内平方和 | 所属中心までの二乗距離の合計 |
| `aggregate(X, by=list(cluster=labels), FUN=mean)` | 元の単位の列を群別に平均する | 群を行、測定値を列とするデータフレーム |
| `table(factor(labels, levels=...))` | 指定した群順で件数を集計する | 群ごとの件数。平均の行と同じ順序で結合する |
| `match(chosen, data$id)` | 指定IDの位置を探す | 初期中心に使う行番号 |

`options(digits=16)`は表示の桁数を指定します。標準化の定義と中心の列順をPythonと揃えましょう。配列の行番号とデータのIDは別のものです。

## 6. 主例で確認する結果

主例は比較用`baseline`のk=2と、変更対象`candidate`のk=3を計算します。件数はk=2で50・100、k=3で50・56・44、群内平方和はそれぞれ約220.879294、139.099201です。これは指定条件での結果で、番号順が異なる表示もあります。

数値の低下だけでk=3が正しいとはいえません。群数を増やすことの意味、解釈しやすさ、目的も必要です。群内平方和は分類精度や将来性能ではありません。種類が3種類あるからk=3が正解とも結論しません。

群の特徴は、まず件数と元のcm単位の4平均を読んで説明します。例えば「この群は、別の群より花弁の平均長が大きい」と測定値で述べます。番号の大小から特徴を推定しません。

## 8. 図の読み方

描画用PCAは標準化した4列から一度だけ計算します。群分けは4次元で実施し、PC1–PC2座標は表示だけに使います。両パネルは同じ座標・範囲・縦横比です。PC1とPC2の寄与率は約72.96%・22.85%、得点は無次元です。
