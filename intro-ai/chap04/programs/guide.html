第5回：プログラムの使い方・学び方

演習スライド ／ 図解教材 ／ 図解教材の使い方

1．保存して、学ぶ準備をする

この演習では、端末の分類と架空の機器貸出の規則を使います。答えを予想し、実行し、一つ変えた結果の理由を説明することが目標です。学校の実際の貸出規則ではありません。

Notebookを保存 ／ Python版を保存 ／ 一式ZIPを保存

Notebookを中心に進めます。ZIPにはNotebook・Python版・このマニュアル・Notebook用requirementsを収録しています。ZIPを使う場合は先に展開してください。Notebookは単体で動き、隣のPythonファイルやJSONファイルを読み込む必要はありません。

ファイルを授業用フォルダーに保存します。ブラウザーの画面で読むだけではPythonは実行されません。GitHub Pagesではファイルを配布し、実行は自分のPCのVS Codeで行います。 図解教材はブラウザーだけで操作できます。

2．VS Codeとカーネルを確認する

  1. これまでの授業で使ったVS CodeとPython環境を開きます。WSLを使っている場合は、VS CodeがそのWSLへ接続していることを確認します。
  2. 保存した knowledge_reasoning.ipynb を開きます。WSLを使う場合は、授業で使っているWSL側のフォルダーへファイルを置きます。
  3. 右上の「カーネルの選択」で、授業用venvのPythonを選びます。すでに登録済みなら「AI course」など授業で使ったカーネルを選びます。
  4. 「カーネルの再起動」の後、「すべて実行」を選びます。

カーネルはセルのPythonを実行する環境です。ノートの内容だけを表示する画面とは役割が異なります。授業用venvを再利用し、この演習のために別のPythonを入れ直す必要はありません。コード本体はPython 3.10以降の標準ライブラリだけを使います。

カーネルが見つからないとき

VS CodeのPython・Jupyter拡張機能を、使っている環境（WSLならWSL側）で利用できるか確認します。次にターミナルで既存の授業用venvを有効化してから、必要な場合だけ次を実行します。授業で venvc を使っている場合は、先にそれを実行して (class) を確認します。

python -c "import sys; print(sys.executable)"
python -m pip install ipykernel
python -m ipykernel install --user --name ai-course --display-name "AI course"

Pythonのパスが授業用venvを指していない場合は、インストールへ進まず環境を確認してください。登録後にカーネル選択を開き直します。ダウンロード名の末尾が .ipynb.txt になっていないかも確認します。

3．基準の結果を読む

最初は入力もコードも変えず、上から全セルを実行します。セル「基準と固定比較を実行」の出力で、次を確認してください。

観察する場所 成功の目印 説明する問い
isa のスマホ→コンピュータ yes、経路はスマホ→携帯型端末→コンピュータ どの矢印をたどったか？
baseline の trace R1→R2、貸出候補まで追加 R3が使えない条件は何か？
with_reservation R1→R2→R3、貸出準備可 基準に何が加わったか？
without_training 適用規則なし 最初のどの条件が欠けたか？

facts は比較しやすい文字列順で表示されます。推論の順序は trace を読みます。 unknown は、未知語または経路がないことを示します。「現実にも違う」と断定する答えではありません。cycle は循環を検出して探索を止めた結果です。

4．予想して、一つ変える

元の FACTS・PARENTS と基準の baseline_result を書き換えず、コピーで実験します。各実験の前に結果を予想し、実行後に「変更した条件／リンク→使えた規則／経路→結論」を言葉にします。

実験A：予約確認を追加する

予想： 基準に「予約確認済み」が加わると、R3まで使えるでしょうか。

Notebookの「自分で一つ変える：予約確認を追加」の直後のセルを実行します。

trial_facts = set(FACTS)
trial_facts.add("予約確認済み")
trial_result = forward_chain(trial_facts, RULES)
print(json.dumps(trial_result, ensure_ascii=False, indent=2))
print("元の事実:", FACTS)

確認： trace はR1→R2→R3、結論に「貸出準備可」が加わります。元の FACTS に予約確認済みが加わっていないことも確認します。R3のどの条件を新しく満たしたか説明しましょう。

実験B：講習修了を除く

予想： 予約確認を追加した状態を引き継がず、基準のコピーから講習修了だけを除くとどうなりますか。

Notebookの末尾に新しいコードセルを追加し、次を貼り付けて実行します。先に全セル実行で関数と json を読み込んでおきます。

without_training = set(FACTS)
without_training.discard("講習修了")
comparison = forward_chain(without_training, RULES)
print(json.dumps(comparison, ensure_ascii=False, indent=2))
print("元の事実:", FACTS)

確認： trace は空で、適用規則はありません。R1の条件が足りず、R2・R3へ進めないことを説明します。「貸出不可」を導いた結果ではありません。

実験C：未知だった上位概念へのリンクを追加する

予想： 「コンピュータ→電子機器」を追加すると、スマホから電子機器までたどれますか。

Notebookの「自分で一つ変える：知識を追加」の直後のセルを実行します。

trial_parents = dict(PARENTS)
print("追加前:", isa_path(PARENTS, "スマホ", "電子機器"))
trial_parents["コンピュータ"] = "電子機器"
print("追加後:", isa_path(trial_parents, "スマホ", "電子機器"))
print("元の知識は保持:", "コンピュータ" not in PARENTS)

確認： 追加前は unknown / unknown_term、追加後は yes / reachable です。スマホ→携帯型端末→コンピュータ→電子機器の経路ができます。この関係は今回与える教材内の定義です。

5．図とコードを結び付ける

  • 関係をたどる：経路・未知語・循環を図で観察し、Notebookの isa と比べます。図解側の通常編集は元の概念の範囲なので、電子機器の追加実験はNotebookで行います。
  • 事実から進む：予約確認を追加／講習修了を外して、同じR1〜R3の結果を比較します。
  • 根拠を説明：R1→R2の追加順序と、結論からR2→R1へ戻る説明順序を区別します。

Python演習はis-a探索と前向き推論です。図解教材のフレーム・後ろ向き推論・世界仮説は追加の教育用実装で、Pythonにも実装されているとは扱いません。

6．元に戻す・困ったとき

  • 実験用セルは毎回、元データから新しいコピーを作ります。基準を再確認するときはカーネルを再起動し、先頭から全セルを実行します。
  • 元データや関数まで編集して戻せなくなった場合は、作業ファイルを別名で保存してから、配布Notebookをもう一度保存します。
  • NameError が出たら、上の定義セルを飛ばしていないか確認します。最初から全セル実行すると依存する定義がそろいます。
  • ZIP内の guide.html はオフラインで読めます。図解教材・スライドへの移動は公開サイトへつながるので、その場合はネット接続が必要です。

Pythonファイルを使う場合

授業用venvを有効化し、保存したファイルのフォルダーで実行します。

python knowledge_reasoning.py --demo

基準と固定比較をまとめて表示します。照合用JSONを読む場合は --demo --json を指定します。Python版だけなら追加パッケージは不要です。自由な入力変更は、上のNotebookのコピーを使う手順で行います。

uvを使っている人は uv run --no-project python knowledge_reasoning.py --demo でも実行できます。ZIP内の requirements.txt は既存のNotebook検証環境の依存一覧です。すでに動く授業用カーネルがあれば、環境を入れ替える必要はありません。
