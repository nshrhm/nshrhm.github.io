形態素と単語

形態素は、意味や文法的機能を担う最小の単位。

「単語」といつも同じ区切りとは限らない。

解析器・辞書・目的によって、採用する単位や品詞体系は異なる。

形態素を単純に単語の別名だと覚えないでください。 今回は限られた辞書の単位を使います。活用の分解を網羅するものではありません。

分割と品詞を対応させる

「猫が眠る」 → 猫 ／ が ／ 眠る

表層形 教材辞書の品詞
猫 名詞
が 助詞
眠る 動詞

区切りだけを得る処理と、品詞などを付ける処理を区別する。

表層形は入力に現れた文字の並びです。 この例の品詞は教材辞書に書いてあります。モデルが新しく学習した結果ではありません。

字種分割では足りない

字種の変わり目：猫 ／ が ／ 眠 ／ る

教材辞書：猫 ／ が ／ 眠る

ひらがな・漢字の境界と、語の境界は一致しない。

操作して確かめる

昨年度の正規表現による字種分割を、比較の対象にします。 長音をカタカナに含めても、全ての語の境界や品詞が分かるわけではありません。

辞書から候補を作る

各位置で一致する表層形を探し、終了位置へつなぐ。

研究生活 → 「研究」「研究生」などの候補

候補には品詞とコストを持たせる。今回のコストは人が設定した教材用の値。

辞書にある候補が一つとは限りません。 実用解析器では学習したコストや接続の情報を使いますが、今回のモデルは単語コストだけです。

候補経路を比べる

経路 単語コスト 合計
研究 → 生活 1＋1 2
研究生 → 活 1＋5 6

長い語を先に選ぶことと、経路全体のコストを小さくすることは異なる。

研究生活は、処理規則を説明するための入力です。 最長一致の局所的な判断で選ぶ経路が、合計コストの最小経路になるとは限りません。

最小コストの経路

各文字位置までの最良コストを記録する。

候補：到着までのコスト＋次の単語コスト

終端までの最小値と、その経路を取り出す。

活のコストを5→0にすると、研究生／活の合計は1。

操作して確かめる

動的計画法では途中の計算を記録して利用します。 この教材では同点を辞書の掲載順で比べます。得られた最小値は、この辞書とコストのもとでの最小値です。

未知語に出会ったら

辞書にない文字も、1文字ずつ「未知」の候補にする。

未知のコストは1文字10。入力を勝手に捨てない。

「猫が笑う」の「笑」「う」は、この小型辞書では未知。

未知という表示は、その言葉が存在しないという意味ではない。

辞書には猫、犬、が、眠る、走ると分割比較用の語しかありません。 未知文字も常に候補に含めるという教材用規則です。文字列を連結すると元の入力へ戻ることを確かめます。

形態素解析の次に

構文解析：語の係り受けや構造を調べる。

意味解析：構造などから意味の表現を考える。

分割・品詞だけで、文脈や意味が全て確定するわけではない。

MeCabの実用的な処理と、今回の小型辞書モデルを区別する。

前処理からどのような情報を得て、何がまだ分からないのかを説明しましょう。 本日は構文木の探索や意味表現の実装には進みません。

コーパスを決める

自作の4文を、それぞれ1文書として使う。

  • 猫 が 眠る
  • 犬 が 眠る
  • 猫 が 走る
  • 犬 が 走る

以下の統計は、この明示した空白区切りに対する値。

コーパスは文章を集めたデータです。 ここでは辞書解析の結果が変わる影響と、統計計算の影響を分けるため、区切り済みの4文を固定します。

回数を数えるBoW

語彙の順序：猫・が・眠る・犬・走る

「猫 が 眠る」 → [1, 1, 1, 0, 0]

Bag-of-Wordsは、文書内の語の出現回数を並べる。

語順を入れ替えても同じ回数なら、同じ表現になる。

ベクトルの各位置と語彙の対応を確認してください。 単語表現と文書表現は対象が異なります。BoWでは今回は一文書を一行で表しています。

bigramは隣り合う二つ

文頭 → 猫 → が → 眠る → 文末

隣り合う組を数える。異なる文の末尾と先頭をつながない。

「が」の次：眠る2回、走る2回。

語彙は5語＋文末。文頭は予測される語に含めない。

予測の対象を決めないと、分母が変わります。 文頭と文末は処理用の記号です。実際に入力する語と混同しないでください。

次の語の確率

平滑化なし：P(眠る｜が)＝2／4＝0.5

P(猫｜が)＝0／4＝0

これはコーパスの数え上げによる条件付き確率。

「観測されなかった」と「日本語として不可能」は違う。

操作して確かめる

縦棒の右側が、分かっている文脈です。 コーパスが小さいため観測されない組合せは多くあります。ゼロという結果だけで言語全体の可能性を否定できません。

加算平滑化で比べる

P(次の語｜文脈)＝(回数＋α)／(文脈の回数＋α×語彙数)

α＝1、語彙数6：「が」の分母は4＋6＝10

眠る：3／10＝0.3、猫：1／10＝0.1

全6候補の確率を足すと1になる。

観測のない候補にも確率を配るため、観測された候補の確率も変わります。 加算平滑化は説明しやすい方法ですが、この方法があらゆる用途で最適という意味ではありません。

頻度だけで特徴を選べるか

「が」は全ての文書に現れる。

「猫」は4文書のうち2文書に現れる。

よく現れることと、文書を区別する手掛かりになることは異なる。

TFとIDFを組み合わせて比べる。

助詞が多く現れるという観察自体は誤りではありません。 文書の特徴を比べたいという目的に対して、文書全体での現れ方も使います。

TFとDFを分ける

TF＝文書内の語の回数／その文書の語数

DF＝その語を含む文書の数

先頭文書の猫：TF＝1／3、DF＝2

同じ文書で猫を2回にしても、その文書によるDFの増加分は1。

TFは文書ごとに計算し、DFは文書集合全体で数えます。 DFを総出現回数と取り違えないことが、今日の重要な確認点です。

TF-IDFを計算する

IDF＝ln(文書数／DF)、TF-IDF＝TF×IDF

先頭文書の猫：(1／3)×ln(4／2) ≈ 0.231049

が：(1／3)×ln(4／4)＝0

今回は自然対数。平滑化・ベクトル正規化は行わない。

操作して確かめる

TF-IDFには実装によって異なる定義があります。 比較する時は対数の底や正規化の有無をそろえてください。がの値がゼロでも日本語に不要という意味ではありません。

文書を追加すると

「猫 が 眠る」を1文書追加する。

先頭文書のTFは1／3のまま。

猫のDFは3、文書数は5。IDF＝ln(5／3)。

先頭文書のTF-IDFは約0.170275へ変わる。

変更したのは文書集合であり、先頭文書の語数や回数は変えていません。 既存文書の数値も、比較対象の文書集合によって変わることを観察してください。

統計から言えることの範囲

bigram：近い語のつながり。長い文脈の全ては扱わない。

TF-IDF：文書集合内での特徴。意味の正しさを保証しない。

コーパスの量・偏り・区切り方が結果へ影響する。

小さな教材データの値を、日本語全体の統計だと受け取らないでください。 学習に使うデータと評価に使うデータを分ける考え方は、自然言語処理でも重要です。

one-hotで単語を表す

語彙：猫・が・眠る・犬・走る

猫＝[1,0,0,0,0]、犬＝[0,0,0,1,0]

別の語は別の位置を1にする。

識別はできるが、似た使われ方はこの表現に直接入っていない。

one-hotは一つの語を表すための表現です。 先ほどの文書のBoWと見た目が似ていても、表す対象と値の意味が異なります。

周辺の語を数える

左右1語を文脈とし、文の境界を越えない。

猫の共起：が2回 → [0,2,0,0,0]

犬の共起：が2回 → [0,2,0,0,0]

この4文では、猫と犬の共起表現が一致する。

同じような周辺語が現れる単語を、数値で比べる考え方です。 今回の一致は小さなコーパスが原因です。猫と犬が同じ意味だという結論にはなりません。

コサイン類似度

コサイン類似度＝内積／(一方の長さ×他方の長さ)

one-hotの猫・犬：内積0 → 類似度0

共起の猫・犬：内積4、長さ2・2 → 類似度1

ゼロベクトルを含む場合は未定義。

分母の長さは要素の二乗和の平方根です。 未定義をゼロと表示すると、情報がない場合と直交する場合を混同します。

表現と窓幅を変える

one-hotと共起回数を切り替える。

左右1語→2語に変え、どの列が増えるか確認する。

共起表は数えた結果。まだWord2Vecの重みではない。

操作して確かめる

各行のラベルを見て、どの単語を表しているか確認します。 文脈の範囲を広げると、得られる情報も変わります。窓幅が大きいほど常に良いとは限りません。

Word2Vecの二つの向き

CBOW：周辺語から中心語を予測する。

Skip-gram：中心語から周辺語を予測する。

今回はSkip-gramを小さく実装する。

予測に役立つように、単語に対応するベクトルを学習する。

Word2Vecは単に単語の出現回数を並べる手法ではありません。 学習の向きを混同しないように、入力と予測対象を矢印で示してください。

中心語と周辺語の組

「猫 が 眠る」、左右1語：

猫→が、が→猫、が→眠る、眠る→が

4文で16組。文の順、中心位置、周辺位置の順に処理。

語彙5語、入力ベクトル・出力ベクトルは各2次元。

同じがという中心語に対して、複数の予測対象があります。 一つの組を強く当てることと、全ての組の平均で良くなることを区別して観察します。

予測確率から損失へ

中心語の入力ベクトルと、各候補の出力ベクトルの内積を計算。

softmax：指数をとり、全5候補の合計で割る。

損失＝−ln(正解の周辺語に与えた確率)

まず「猫→が」の1組だけを更新する。

操作して確かめる

全ての候補について確率を計算します。 計算を安定させるため内積の最大値を引いてから指数をとります。この操作でも確率は変わりません。

更新する二種類のベクトル

損失の勾配から、中心語の入力ベクトルと候補語の出力ベクトルを更新する。

全勾配は更新前の値から計算する。

学習率0なら変化なし。基準は学習率0.1、20エポック。

単語の表示には学習した入力ベクトルを使う。

出力側の計算に更新済みの入力を使うと、意図した勾配更新ではなくなります。 詳しい式はプログラム解説にあります。まず画面で、どの行が変わるのかを見てください。

学習結果の読み方と限界

1組の損失と、全16組の平均損失を区別する。

似た文脈を予測するための表現であり、人間と同じ意味理解の証明ではない。

静的な単語表現は、同じ語の文脈ごとの意味を直接区別しない。

単語の足し引きが、どの語・データでも成功するとは限らない。

小さなデータと二次元のモデルで、実用的な意味関係の獲得を保証してはいけません。 入力とシードを固定した比較は再現性の確認であり、性能評価とは異なります。

音声認識と音声合成

音声認識：音声 → 文字列

音声合成：文字列 → 音声

音声応答システムでは、認識の後に応答の処理を行い、合成して読み上げる。

今日は認識での候補選択を扱う。

スライドの読み上げ音声を作る工程は音声合成です。 今回の演習では録音や音声の生成を行いません。処理の方向を確実に区別してください。

波形から候補へ

概念図：音声波形 → 短い時間ごとの特徴 → 音響情報 → 文字列候補

音響情報と、語の並びや出現に関する言語情報を利用できる。

雑音・発音・録音条件・文脈によって判断が変わり得る。

これは処理を説明するための概念図で、今回のコードが波形を処理するという意味ではありません。 実用システムには統合して学習する構成もあります。全方式が独立した部品を同じようにつなぐわけではありません。

二つの情報で候補を比べる

人工例：「あめ」の候補を雨・飴とする。

候補 音響尤度 事前確率 積（λ＝1）
雨 0.6 0.2 0.12
飴 0.4 0.8 0.32

音響だけなら雨、両方を使うと飴。

操作して確かめる

ここに示す数値は人が設定した教材用の値です。 実際の録音から推定した値ではなく、雨と飴の認識率を示すものでもありません。

言語情報の重みを変える

順位スコア＝ln(音響尤度)＋λ ln(事前確率)

λ＝0：音響情報だけ。λ＝1：積の大小と同じ順位。

スコアを認識の正答率と解釈しない。

もっとも高い候補でも、正しい文字列とは限らない。

対数を使うと積を和として扱えます。 確率を対数へ入れるため、ゼロ以下の値を受け付けません。誤入力のときに古い結果を正しい結果として見せないようにしています。

認識の誤りを考える

正解と比較して、置換・削除・挿入を区別する。

例：正解「猫 が 眠る」／出力「犬 が 眠る」→ 置換1件

正解データと区切り方をそろえて評価する。

今回の候補選択は、実音声での精度評価ではない。

正解の文章を見ずに、もっともらしさだけで精度を評価できません。 表記や分割条件によって数え方が変わるため、比較条件を先に決めることが大切です。
