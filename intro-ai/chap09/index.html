処理と判断を区別する

段階 例

画素と座標

グレースケール画像：各画素を明るさに対応する数値で表す。

今回は行rが下方向、列cが右方向、0始まり。

8ビットの値の範囲は0〜255。RGBは赤・緑・青の3成分を使う。

教材の小さな値は実写真から取得したものではありません。 RGBからグレースケールへの変換は、色の情報を減らす処理でもあります。

今回の人工画像

0 0 0 0 0
0 2 2 2 0
0 2 9 2 0
0 2 2 2 0
0 0 0 0 0

中心は (2,2)。周囲の2に比べ、中心の9が大きい。

全ての処理で行と列の意味をそろえます。 図の色は表示用に調整されるため、異なる図は数値も見て比較します。

二値化の規則

しきい値tに対し、

画素値 > t なら1、それ以外は0。

値がしきい値と等しいときは0。前景を1、背景を0と呼ぶ。

ここでは二値化のルールを一つに固定しています。 前景は選んだ規則に適合した画素であり、物体として正しい領域とは限りません。

しきい値を一つ変える

人工画像で、t=1 → 前景9画素。

t=2 → 中心だけの1画素。t=9 → 0画素。

予想：しきい値を大きくしたとき、前景は増えるか。

操作して確認する

等号が含まれないことを確認しましょう。 中心の値やしきい値のどちらか一つだけを変え、理由を説明してください。

明るさの変更と飽和

画素値にbを足し、0〜255の範囲へ収める。

例：250 + 10 → 表示用の画素値は255。

飽和すると異なる入力が同じ値になる。変換は元に戻せるとは限らない。

トーン調整には多くの方法がありますが、演習は単純な加算だけです。 正規化相関の説明で扱う加算は、飽和が起きない条件に限定します。

小領域を順に調べる

3×3を、5×5画像に歩幅1で動かす。

画像内に収まる場所だけ計算する valid：出力は3×3。

出力(0,0)は入力の左上3×3に対応し、その中心は入力(1,1)。

出力の座標と入力画像の中心座標を区別します。 境界をゼロで埋める方式とは結果と形が変わります。今回、外側を補いません。

線形フィルタの積和

対応する画素とカーネルを掛け、合計する。

出力(r,c) = Σ K(i,j) × I(r+i,c+j)

今回はカーネルを反転しない相関演算。数学的な畳み込みでは反転が入る。

CNNや画像処理では、この相関演算も畳み込みと呼ばれることがあります。 計算する規則を明示すれば、非対称なカーネルの向きの混同を防げます。

平均化フィルタ

3×3の9画素を足して9で割る。

中心領域：2が8個と9が1個。

(2×8 + 9) / 9 = 25/9 ≈ 2.777778

大きな孤立値の影響は周辺の出力にも広がる。

平均は外れた値の影響を受けます。 滑らかになったことと、必要な輪郭が保存されたことは別に確認します。

メディアンとMAX-MIN

メディアン：9画素を並べ、5番目を採用 → 2。

MAX-MIN：最大値−最小値 → 9−2=7。

これらは、固定カーネルの積和とは異なる処理。

中央値はこの例では元の周囲の値2になります。 どんなノイズでも完全に除去できるという意味ではありません。

平滑化の結果を比較する

中心の9を2へ変更すると、中心領域の平均も中央値も2。

基準画像では平均25/9、中央値2。

問い：変化に反応した量と、変わらない量を説明できるか。

操作して確認する

まず平均と中央値の両方を基準画像で観察してください。 次に中心だけを変え、出力のどこまで変化したかも確かめます。

ラプラシアンの応答

 0  1  0
 1 -4  1
 0  1  0

中心：2+2+2+2−4×9 = −28。

一定値の領域では、このカーネルの応答は0。

ここで負の値は計算ミスではありません。 原画像の明るさと、フィルタの応答という二つの数値を分けて扱います。

符号を残す意味

Sobel xは左右方向の明るさ変化に反応する。

-1  0  1
-2  0  2
-1  0  1

暗→明と明→暗で符号が変わる。負を0にすると片側の情報を失う。

符号付き実数として計算してから、表示だけを調整します。 ReLUが必要なCNNの段階と、エッジ観察の目的を混同しないことが大切です。

明暗反転を試す

人工画像を「9−画素値」にすると、

中心のラプラシアン応答は −28 → +28。

絶対値表示では両方28。符号の違いは見えなくなる。

操作して確認する

絶対値を取ることも情報を減らす操作です。 応答の大きさを見たい目的と、明暗変化の向きを見たい目的を区別します。

領域から特徴量を作る

二値化した前景を、少数の数値で要約する。

  • 面積：1の画素数
  • 重心：前景画素の行・列の平均
  • 投影：行ごと・列ごとの前景画素数

同じ規則で表した特徴を比較する。

ここでの面積の単位は画素数です。 実際の平方メートルへ換算するには、撮影条件など別の情報が必要です。

面積と重心を計算する

t=1の前景は中央3×3。面積A=9。

重心 = (Σr×M(r,c)/A, Σc×M(r,c)/A) = (2,2)。

A=0では割れない → 重心は未定義。

背景も含めた全画素の座標平均ではありません。 空の領域の重心をゼロとすると、左上に物体がある場合と混同します。

投影で残る情報・消える情報

行投影も列投影も [0,3,3,3,0]。

1 0    0 1
0 1    1 0

この二つは面積・重心・行投影・列投影が同じ。画像は異なる。

特徴量が同じなら元画像も同じ、とは言えません。 どの違いを残したいかに応じて、特徴を選ぶ必要があります。

しきい値と特徴量の関係

t=1：面積9、重心(2,2)。

t=2：面積1、重心(2,2)。

t=9：面積0、重心は未定義。

操作して確認する

一つの特徴が変わらなくても、別の特徴は変わる場合があります。 中心が同じ位置にあることだけで同じ大きさの物体とは判断できません。

プーリングとCNNの特徴

2×2・歩幅2の最大値プーリング：4×4 → 2×2。

行数・列数は各1/2、画素数は1/4になる。

CNNの画像ごとの特徴は、画像を入力したときの中間層の出力。重みはモデルのパラメーター。

昨年度資料の重みを画像の特徴ベクトルとする説明を区別して修正しています。 今回の演習にCNNの再学習は追加せず、第7回の学習済みの考え方につなげます。

テンプレートで位置を探す

小さな基準画像Tを、探索画像Iの各位置と比較する。

各位置に評価値を付ける → 評価マップ → 候補の左上位置。

移動を調べる方法で、回転や拡大を自動で調べるわけではない。

似た場所を見つけることと、その対象が何であるかを理解することは同じではありません。 テンプレートと処理対象の条件を先にそろえます。

SSDは差の二乗和

SSD(r,c) = Σ (I(r+i,c+j) − T(i,j))²

小さい値ほど画素値が近い。全画素が同じなら0。

MSEはSSDを画素数で割った値。同じ大きさなら順位は同じ。

負の差も二乗で正になります。 この授業のSSDには画素数による割り算を含めません。

全位置の評価マップ

探索画像4×5、テンプレート2×2 → 評価マップ3×4。

基準テンプレート [[1,2],[3,4]] は、左上(1,2)でSSD=0。

選択した位置の4画素と、評価マップの1要素を対応させる。

操作して確認する

操作教材の赤枠は選択した比較位置を示します。 画像に収まる12箇所を全て比較し、途中の一つだけで最良と決めないようにします。

最良値と同点候補

最小SSDの位置が複数ある場合もある。

教材は同点候補を全て示し、行→列の順の先頭を表示する。

最良候補があることは、探した物体が存在する証明ではない。

何も一致しない画像にも、SSDの最小位置はあります。 必要に応じて閾値で保留する基準を設けますが、その閾値は別データで検証します。

明るさが変わるとSSDはどうなるか

T=[[1,2],[3,4]]に、10を加えたパッチを比較。

差は各画素10 → SSD=4×10²=400。

形の並びが同じでも、画素値の差を評価するSSDは変わる。

ここでは0から255の範囲内なので飽和は起きません。 探索画像全体を明るくすると、SSDの最良位置自体も変わる場合があります。

平均を引いて比較する

各パッチとテンプレートから、それぞれの平均を引く。

Tの平均2.5 → [−1.5,−0.5,0.5,1.5]。

T+10の平均12.5 → 同じ並びになる。

共通の平均を引くのではなく、比較する各領域の平均を引きます。 この操作で一定の加算成分が消えることを小さな例で確認してください。

ZNCCの規則

平均を引いた値をI′、T′とすると、

ZNCC = Σ I′T′ / √(Σ I′² × Σ T′²)

大きい値ほど正の対応が強い。SSDとは選ぶ向きが逆。

非一定領域・飽和なしなら、正の倍率と一定の加算に対応する。

平均中心化した正規化相関をZNCCと呼びます。 分母が定義できる条件では、値はマイナス1から1の範囲です。

相関が定義できない場合

パッチまたはテンプレートが一定値 → 平均を引くと全て0。

分母0 → 未定義。教材はNone／nullで表し、候補から除く。

全候補が未定義なら「有効な候補なし」。

一定画像に1という値を与えて、完全一致と説明しません。 ライブラリごとの例外処理と区別し、この教材の規則として記録します。

明るさと一定テンプレートを試す

TとT+10：SSD=400、ZNCC=1。

探索画像への加算0→10で、二つの最良位置を比較する。

一定値テンプレートでも試し、未定義を説明する。

操作して確認する

正の倍率と一定の加算に対応できるのは、飽和や丸めによる形の変化がない条件です。 相関1を認識正解率100パーセントと解釈しないでください。

回転・大きさ・遮蔽の限界

90度回転したT=[[3,1],[4,2]]とのSSDは、元の位置で10。

画素の対応が変わるので、明るさの正規化だけでは補えない。

複数の向きや大きさを比較すると、候補数と計算量も増える。

向きを試すことと、どの向きにも自動的に不変な特徴を作ることは異なります。 欠けた対象や変形した対象についても別の検証が必要です。

文字認識・画像検索との関係

文字認識：画像のパターンから文字候補を選ぶ。

画像検索：同じ特徴抽出法で作った表現を比較する。

文字の候補に言語情報を加える考え方は第10回につながる。

実用の文字認識を四つの画素だけで再現したという意味ではありません。 画像情報に言語情報を加えても、誤りがなくなる保証はありません。

位置・種類・本人性は異なる問い

  • 検出：どこにあるか
  • 分類：どの種類か
  • 本人照合：申告された人と同じか

顔の位置を見つけても本人照合の成功を意味しない。今回は人工図形のみ。

顔画像や個人情報を収集する課題ではありません。 同じ画像処理という言葉でも、目的と正解の定義が違うことを確認します。

評価値と正解率を分ける

SSDやZNCCは、定めた式による比較値。

正解位置の注釈を持つ別の画像で、見逃し・誤検出を調べる。

しきい値を調整した画像だけで、汎化性能を主張しない。

この授業の人工例は計算が正しいかを確かめるためのものです。 実際の性能評価には、照明や向きなど条件が異なるデータも必要です。
