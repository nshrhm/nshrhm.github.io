強化学習で学んだ価値と、探索で計算する値は、どちらも行動選択に役立ちます。 ただし、今回のニムはルールと終端の勝敗から値を計算し、学習はしません。

探索と学習

方法 今回の意味
探索 候補とその先を調べ、選ぶ手を計算する
学習 データや経験から評価・方策などを変える

探索と学習は組み合わせられるが、同じ処理ではない。

木を調べた回数が増えても、それだけでモデルが訓練されたことにはなりません。 後半では学習した評価を探索と組み合わせる例を紹介します。

ゲームの性質を分ける

  • 完全情報：手を選ぶ時点で、それまでの手や局面を知れる。
  • 決定的：同じ局面と手から、次局面が一つに決まる。
  • 二人零和：一方の利得は他方にとっての損失。

完全情報と、確率的要素がないことは別の性質。 今回のニムは、この三つを満たす教材モデル。

情報が見えるかと、偶然によって結果が分かれるかは別の軸です。 以下は交互に手を選ぶ二人零和の決定的な例に絞ります。

ニムのルール

二つの山から、交互に石を取る。

  • 一回に一つの山から、1個以上取る。
  • 最後の石を取った側が勝つ。
  • 初期局面は左3個、右2個。

別のニムのルールと混ぜず、この勝利条件で考える。

一度の手で二つの山から取ることはできません。 最後を取ると負けという変種もありますが、この教材は最後を取ると勝ちです。

局面には手番も含める

局面 = （左の石数、右の石数、手番）

MAXを先手、MINを後手として開始する。

同じ石数でも、手番が変わればMAXから見た勝敗は変わる。

例：(0,0,MIN) はMINが指せない → MAXが勝った終端。

表示の山の数だけを状態とすると、誰の勝ちか判定できません。 プログラムでは手番を1とマイナス1で明示して反転します。

合法手を列挙する

(3,2) の合法手は五つ。

左から1個・2個・3個、右から1個・2個。

基準の順序：山番号昇順 → 取る個数昇順。

左から1個取ると (2,2)、手番は交代。

操作：局面と合法手

合法手はルールが許す候補です。この時点では、候補の良し悪しはまだ決めていません。 操作教材で一手指し、石数だけでなく手番も変わることを確認します。

ゲーム木を作る

根：現在の局面。枝：合法手。子：その手の後の局面。

木の生成だけでは最善手を選べない。

終端の利得を定め、相手の選択を考えて根へ値を戻す必要がある。

同じ局面でも、別の手順で到達した節点は別に数える。

昨年度のニムコードは、主に木の列挙を行っていました。 今回は評価と手の選択を追加します。キャッシュを使わず、木の節点数を数えます。

終端の利得

ニムの終端：両方の山が0。

結果 MAXから見た利得
MAXが勝った +1
MINが勝った −1

終端では着手しない。固定木の数値例は、別の利得尺度を使う。

途中の局面で石が少ないことと、勝ちが確定したことは異なります。 ニムでは勝敗をプラス1とマイナス1で表し、固定木では計算練習の整数利得を与えます。

MAXとMIN

すべての値をMAXの視点にそろえる。

  • MAXの番：子の値の最大を選ぶ。
  • MINの番：子の値の最小を選ぶ。

相手も自分に有利な手を選ぶ、と仮定して計算する。

MINは数値を小さくすることで自分に有利な結果を選びます。 手番のたびに利得の意味を変えると計算を間違えるので、常にMAXから見ます。

手計算用の固定木

根はMAX、A・B・CはMIN。

MINの節点 終端1 終端2
A 3 5
B 2 9
C 0 4

基準探索順：A→B→C、各行は左から右。

この木はニムの一部を切り抜いたものではなく、教材用に独立して定めた木です。 まず相手が選ぶ各行の最小値を予想してください。

MINの値を先に求める

A = min(3,5) = 3

B = min(2,9) = 2

C = min(0,4) = 0

MAXはBの9を自由に選べない。Bで選ぶのはMIN。

大きい数字だけを見ると9のあるBを選びたくなります。 しかしBへ進んだ後に手を選ぶのは相手なので、2を返すのがミニマックスの考え方です。

根へ値を戻す

根 = max(3,2,0) = 3、選ぶ手は A。

この計算は「相手も適切に選ぶ」という条件での値。

操作：Bの終端2を6に変える

予想：Bの値と根の選択はどう変わる？

Bの葉を2から6に変えると、Bの最小値は6になります。 他を変えなければ根はBを選び、値は6です。一つだけ変えて比較します。

ミニマックスの手順

  1. 終端なら、その利得を返す。
  2. 打切りなら、推定値を返す。
  3. 子を順番に探索する。
  4. MAXなら最大、MINなら最小を親へ返す。

基準固定木の全探索：10節点を訪問、終端6個を評価。

根と内部の三節点も訪問数に含めるので、評価回数とは一致しません。 再帰処理は同じ手順を子にも適用します。まず終端かを判定する点が大切です。

値と選ぶ手を分ける

値：その局面をどう評価するか。

手：その値を与える子へ、どう進むか。

固定木：値3、手A。 ニム (3,2)：値+1、左から1個 → (2,2)。

ニムの全探索：86節点・終端37個。

結果の数値だけでは、実際に何をすればよいか分かりません。 プログラムは値と手を別々の項目として返します。ニムの手は山番号と個数の組です。

同点なら最初の手

同点のときは、探索順で最初の手を保持する。

更新条件はMAXで「より大きい」、MINで「より小さい」。

A・B・Cがすべて3なら、正順はA、逆順はC。

値が同じでも、選ぶ手は変わり得る。

同点で上書きする実装にすると最後の手を選び、今回の仕様と異なります。 ミニマックスと枝刈りを比べるときは、探索順と同点規則もそろえます。

探索深さを制限する

根の深さを0、A・B・Cを1、終端を2とする。

全探索が大きすぎる場合、途中で探索を打ち切る。

ただし、終端判定を打切り判定より先に行う。

深さ2の終端は、推定値でなく確定した利得を返す。

深さは根から何本の枝を進んだかです。 終端に到達しているなら、勝敗が分かるので、推定に置き換える必要はありません。

打切りで使う評価関数

今回は説明用の推定値を直接与える。

根 A B C
0 1 4 2

推定値はMAXから見た値。終端利得の保証ではない。 実際のゲームでは、局面の特徴や学習したモデルから推定することもある。

この四つの値は、深い探索の答えを正しく近似するよう調整した値ではありません。 浅い探索が間違った選択をする例として、意図的に用意した教材条件です。

浅い探索と全探索を比較

深さ1：max(1,4,2) = 4、手B（推定）。

深さ2：max(3,2,0) = 3、手A（終端から計算）。

深さ0：根の推定値0を返し、手は選ばない。

操作：深さと推定値を変える

深さ1では終端を一つも評価していません。 表示された4を勝敗や確定利得と読み替えず、打切りによる推定だと説明してください。

評価を一つ変える

深さ1の比較ケースをコピーする。

Aの推定値だけ 1→5 に変更。

max(5,4,2) = 5、手A（推定）。

手が全探索と一致しても、推定値5は確定利得3と異なる。

この変更例の基準は深さ1です。深さと推定値を同時に変える実験ではありません。 偶然同じ手になったことと、評価関数が正確になったことを分けて考えます。

水平線効果

打切りのすぐ先にある重要な変化を見落とすことがある。

浅い探索で良く見えても、その先で相手の強い応手があるかもしれない。

深さ・評価関数・局面によって結果は変わる。 「深さを少し増やせば常に十分」とは限らない。

打切りより先が見えないことを、地平線の向こう側にたとえます。 この授業では評価の誤差を小さな固定木で観察し、将棋での具体的な対策実装は扱いません。

αβ枝刈りの目的

同じ条件のミニマックス値を保ち、不要な探索を省く。

相手が選ばないと分かった枝は、その先を全部調べなくてよい。

評価関数・深さ・探索順・同点規則をそろえて比較する。

省略した枝の値を計算したことにはしない。

枝刈りは推定で勝手に候補を捨てる処理ではありません。 既に得た値の範囲から、その枝が上位の選択を改善しないと分かる場合に省きます。

αとβの意味

α：MAX側が既に確保できる値の下限。

β：MIN側が既に確保できる値の上限。

初期値：α = −∞、β = ＋∞。

MAXの子を調べてαを上げ、MINの子を調べてβを下げる。

値の範囲は、現在の探索経路でどの候補を選ぶ可能性があるかを表します。 負の利得もあるため、初期値を0にしてはいけません。

枝刈りの条件

α ≥ β なら、残りの子を探索しない。

MAXには少なくともαの選択肢があり、 このMINでは高くてもβに抑えられる。

等しい場合も、先に見つけた同点の手を保持できる。

今回の実装は等号を含めて枝刈りします。 同点時に最初の手を保持する規則と組み合わせることで、手の選択も一致させます。

固定木で一段階ずつ

Aを調べる：min(3,5)=3 → 根のα=3。

B1=2：Bのβ=2。3≥2なのでB2は未探索。

C1=0：Cのβ=0。3≥0なのでC2は未探索。

操作：一段階進む／最後まで

Aでは二つの葉を調べます。Bでは一つ目の2を見た時点で、Aの3を超える選択肢にならないと判断できます。 B2の9とC2の4は入力として存在しますが、この探索では評価しません。

途中の値は上限・下限

Bで2を見て枝刈りしたとき、分かったのは B ≤ 2。

未探索のB2が−5なら、Bの確定値は−5になる。

それでもAの3を超えないので、根の選択は変わらない。

画面では「上限」「下限」「未探索」を区別する。

枝刈りした内部節点の戻り値を、真のミニマックス値と断定すると誤りになります。 根では全体の必要な比較が済むため、今回の完全探索条件で値3が確定します。

探索順で評価回数が変わる

条件 根の値・手 終端評価
ミニマックス・正順 3・A 6
αβ・正順 3・A 4
αβ・逆順（子も逆順） 3・A 6

操作：正順と逆順を比較

この木では良い候補のAを先に調べることで、後の候補を早く省略できます。 逆順の削減がないことは実装失敗ではなく、順序による違いです。

計算量とニムでの比較

枝数がb、深さがdなら、全探索は概ね bのd乗で増える。

αβの削減率は探索順や木の形による。常に同じ割合にはならない。

ニムはキャッシュなし。訪問節点数と終端評価数を別に比べる。

操作：人間の手 → AIの応手

小さなニムでは終端まで探索できますが、将棋では同じ規模に収まりません。 ここでは実時間の速さを競うのでなく、同じ条件で値と計数がどう変わるかを確認します。

将棋と探索

将棋も、合法手から次の局面を考えられる。

候補が多く、長い手順の先まで全列挙するのは難しい。

探索の工夫と、途中局面の評価が重要になる。

今回の二山ニムの節点数を、将棋の規模に一般化しない。

将棋の駒の持ち方や打つ手など、具体的なルールは今回実装しません。 大きなゲームでは、どこを重点的に調べるかと、途中局面をどう評価するかが課題です。

学習した評価を使う

局面の特徴 → モデル → 価値の推定。

経験から評価を改善し、その評価を探索に利用する構成がある。

探索だけ／学習だけ／両者の組合せを区別する。

推定があることだけで、勝利が保証されるわけではない。

学習した評価は、探索を不要にするとは限りません。 学習済みの値にも誤差があり、探索の計算資源にも制限があることを意識します。

方策と価値

出力 主な役割
方策 各候補の手に、選択の優先度・確率を与える
価値 その局面の結果を推定する

AlphaZeroでは、一つのネットワークが両方を出力し、探索に使う。

方策はどの手を考えるか、価値は局面をどう見るかに関係します。 この説明はAlphaZeroの論文の構成であり、すべてのゲームAIが同じ方式という意味ではありません。

MCTSの概要

候補を選ぶ → 木を広げる → 評価する → 結果を戻す。

訪問回数や評価に基づき、調べる候補へ計算を配分する。

評価方法は一通りではない。 常にランダム対局だけで評価する方法ではない。

今回は考え方の紹介のみ。実装はミニマックスとαβ。

モンテカルロ木探索は、限られた計算をどの候補へ使うかを考える探索です。 AlphaGo ZeroやAlphaZeroでは、方策と価値のネットワークを利用します。

AlphaGo Zero 囲碁。人間の棋譜を使わず自己対戦で学習
AlphaZero 囲碁・チェス・将棋へ同じ学習方式を適用
