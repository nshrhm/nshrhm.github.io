第13回 人工知能とゲーム：プログラムの保存と学び方

目標と保存

ミニマックスとαβの値・手・計数を照合し、一項目変更の結果を説明します。前提はリスト、辞書、関数、最大・最小です。実行部分はPython標準ライブラリのみを使います。

スライド ／ 操作教材 ／ 操作マニュアル

Pythonを保存 ／ Notebookを保存 ／ 一式ZIPを保存

  1. ZIPを保存・展開し、同梱guide.htmlを開きます。以下は同梱ファイルだけで実行手順をたどれます。
  2. VS Codeで展開先を開き、既存venvを有効化し、そのPythonインタープリターを選びます。Python 3.10以上を使い、制作環境の版をそのまま導入する必要はありません。
  3. ターミナルで次を実行します。
python game_search.py --demo

uvを既に使っている場合は uv run python game_search.py --demo でも実行できます。Notebookは既存のJupyter環境で開き、既存venvのカーネルを選びます。「カーネルを再起動」→「すべて実行」を選んでください。カーネルがない場合だけvenv内で python -m pip install -r requirements.txt を実行し、同じvenvを再選択します。システム全体へのインストールは不要です。

成功の目印は固定木の値3・手A、ニムの値+1・手[0,1]（左から1個）、Notebook末尾の「基準入力・結果を保持しました」です。Notebookは同梱Pythonをimportしません。

入力と結果の読み方

固定木は根MAX、A・B・CがMIN、葉[3,5,2,9,0,4]。根の深さ0、終端は2。打切り推定値は[根0,A1,B4,C2]。全利得はMAXの視点です。ニムは二山(3,2)、最後を取ると勝ち。手番1=MAX、−1=MINです。手は[山番号0または1,取る個数]。同点は探索順で最初の手を選びます。

  • value：根の値。深さ打切りを使えば推定です。
  • best_action：選ぶ手。終端・深さ0ではNone（JSONはnull）。
  • visited_nodes：根・内部・評価節点をすべて含む訪問数。
  • evaluations：終端評価＋打切り評価。terminal_evaluationsとcutoff_evaluationsが内訳です。
  • pruned：未探索の枝の根のID。子孫全部を列挙する項目ではありません。
  • trace：enter→evaluate／update／prune→returnの履歴。boundはexact（その探索条件の値）、upper（上限）、lower（下限）。深さ打切りを含むexactも、実際の勝敗を保証する値ではありません。

search_treeとsearch_nimは完全な履歴を返します。--demo --jsonとbaseline_resultは読みやすい要約でtraceを省きます。CLIで履歴も保存するときは python game_search.py --demo --json --trace > result.json。Notebookのbaseline_tree、baseline_nimには履歴を保持します。summaryは元の結果を壊さず要約します。

関数と三つの観察

legal_movesでルールに沿う手を列挙し、apply_moveで入力のコピーから次局面を作ります。search_treeは固定木、search_nimはニムを探索します。内部のvisitは終端判定を先に行い、MAXなら最大・MINなら最小を返します。αβでは上下限を更新し、α≧βで残りの子を省略します。

予想：全探索とαβで根値は違うでしょうか。まず両方を実行し、固定木の3・Aが一致する一方、終端評価6→4、訪問10→8となることを確認します。次に深さ1を実行すると推定4・Bになります。最後にニムを実行し、86節点・終端37個を確認します。説明する問いは「深さで省略する場合とαβで省略する場合の根拠はどう違うか」です。

コピー上で行う六つの変更

Notebookでは各セルの直前に問い・予想・想定結果があります。experiment_configs()の各ケースにはbaseとその深いコピーchangedがあります。順序の基準はαβ、推定値の基準は深さ1です。ほかは基準条件そのもの。毎回一項目だけ変え、先の変更へ上書きして積み重ねないでください。

B1の利得2→6

  • 問い・予想：Bが選ばれるだろうか。実行前に予想を書きます。
  • 手順：Notebookのtrial_leaf_configセルを実行し、trial_leafを元のケースと比較します。
  • 想定結果：値3・A → 値6・B。MINの値も6になる。
  • 説明する問い：相手が9でなく6を選ぶのはなぜか。
  • 復帰：該当セルを編集前に戻し、カーネルを再起動して全セル実行します。

αβの探索順を逆順

  • 問い・予想：根値と評価数のどちらが変わるだろうか。実行前に予想を書きます。
  • 手順：Notebookのtrial_order_configセルを実行し、trial_orderを元のケースと比較します。
  • 想定結果：値3・Aは同じ。終端評価4→6。各子の順序も逆になる。
  • 説明する問い：Aを後に調べると省略が減る理由は何か。
  • 復帰：該当セルを編集前に戻し、カーネルを再起動して全セル実行します。

探索深さ2→1

  • 問い・予想：深さ1でもAを選ぶだろうか。実行前に予想を書きます。
  • 手順：Notebookのtrial_depth_configセルを実行し、trial_depthを元のケースと比較します。
  • 想定結果：確定した根値3・A → 推定値4・B。終端評価0、打切り評価3。
  • 説明する問い：深さ1の4を確定した利得と呼べるか。
  • 復帰：該当セルを編集前に戻し、カーネルを再起動して全セル実行します。

深さ1でAの推定値1→5

  • 問い・予想：推定値だけで手が変わるだろうか。実行前に予想を書きます。
  • 手順：Notebookのtrial_heuristic_configセルを実行し、trial_heuristicを元のケースと比較します。
  • 想定結果：推定値4・B → 推定値5・A。確定利得3とは違う。
  • 説明する問い：手が全探索と一致すれば、推定値も正しいか。
  • 復帰：該当セルを編集前に戻し、カーネルを再起動して全セル実行します。

ニム(3,2)→(2,2)

  • 問い・予想：同じ数の山は先手に有利だろうか。実行前に予想を書きます。
  • 手順：Notebookのtrial_piles_configセルを実行し、trial_pilesを元のケースと比較します。
  • 想定結果：MAX先手の値+1 → −1。訪問86→33、終端37→14。負け局面では同点の最初の手を選ぶ。
  • 説明する問い：なぜ値−1でも合法手が返るのか。
  • 復帰：該当セルを編集前に戻し、カーネルを再起動して全セル実行します。

ミニマックス→αβ

  • 問い・予想：省略によって根値が変わるだろうか。実行前に予想を書きます。
  • 手順：Notebookのtrial_algorithm_configセルを実行し、trial_algorithmを元のケースと比較します。
  • 想定結果：値3・Aは同じ。訪問10→8、終端評価6→4。
  • 説明する問い：未探索のB2・C2の確定値を表示できない理由は何か。
  • 復帰：該当セルを編集前に戻し、カーネルを再起動して全セル実行します。

基準を保持して自分で変更する

from copy import deepcopy
case = experiment_configs()["leaf"]
trial_config = deepcopy(case["base"])
trial_config["leaves"][2] = 6
trial = search_tree(trial_config)
print(summary(trial))

上はNotebookの定義セルを実行した後に新しいセルで試します。.pyで試す場合は自分用にコピーを作り、同じ関数定義の後にこのコードを追加します。配布された基準ファイルは残します。基準入力・基準結果は上書きしません。

困ったとき

ファイルが見つからない場合は展開先とターミナルの場所を確認します。NameErrorならカーネルを再起動して全セル実行します。出力が違う場合は深さ・探索順・方式・手番と変更箇所を確認し、未変更のファイルへ戻します。ValueErrorなら、空欄、小数、山の合計6超過、不正な手を直します。終端では手がNoneになり、apply_moveへ渡してはいけません。

固定木の利得・推定値は−100〜100の整数、深さ0〜2、山0〜4・合計6以下。乱数・学習・キャッシュは使いません。同じ局面への別経路は別の節点です。勝敗値が−1でも、相手の間違いまで禁止しているわけではありません。ミニマックスは双方が最善を選ぶ仮定で解釈します。
