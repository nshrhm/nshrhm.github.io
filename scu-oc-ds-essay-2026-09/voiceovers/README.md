# 音声対応表

全20枚。`slide_01.mp3`〜`slide_20.mp3` をスライド順に1対1で対応させます。
参照形式は `<audio controls src="./voiceovers/slide_01.mp3" type="audio/mpeg"></audio>` です。

資料作成時は未生成でしたが、その後ユーザーが音声生成を確認し、現在は20ファイルすべて存在します（2026年9月25日確認）。今回の汎用化作業では再生成せず、作業前後のSHA-256で同一性を確認しています。既存88枚版の音声も変更していません。

| 番号 | 内容 |
|---|---|
| 01–03 | 導入・疑問・小論文の考え方 |
| 04–08 | 設問・図表読解体験・根拠の選択 |
| 09–11 | 答案の構成・提案・点検 |
| 12–15 | 日程・高3推薦・高3前期・高1と高2 |
| 16 | 今日の一歩 |
| 17 | 質疑応答への案内 |
| 18–20 | FAQ・チェックリスト・出典 |

発表者ノートは日本語の説明原稿です。各枚の時間は `timing.tsv` に記録しています。
スライド6は45秒の黙考を含みます。ノートだけを機械音声にしても45秒の待ち時間は生じません。
スライド17は質疑の案内であり、ノートを読み上げるだけで3分になる設計ではありません。
今回の30分は講師による説明・図表操作・黙考・質疑の合計であり、音声の再生時間ではありません。

追加・削除・順序変更後は、後続の音声参照を再採番し、生成前に `make check` を実行してください。
音声を生成した後は `make check-audio` で存在と形式を検査し、再生品質を別途確認します。
`generate_voiceover.py` は入力から枚数を自動判定します。入力省略時は従来どおり `presentation/slide.md`、出力先省略時は入力ファイル隣の `voiceovers/` です。

## 実行方法（リポジトリのルートから）

まず、通信・MP3生成を行わずに対応を確認します。

```bash
make -C presentation-20260927 voiceovers-dry-run
```

次の直接指定でも同じ確認ができます。dry-runは入力、総枚数、生成範囲、出力先、ファイル名、既存ファイルの有無を表示します。出力フォルダーも作りません。

```bash
uv run python generate_voiceover.py --input presentation-20260927/slide.md --dry-run
```

確認後、音声を生成する場合のコマンドです。新規版の `voiceovers/slide_01.mp3`〜`slide_20.mp3` に保存します。指定範囲の同名ファイルはすべて再生成します。

```bash
make -C presentation-20260927 voiceovers
make -C presentation-20260927 check-audio
```

直接実行する場合は、枚数・出力先を指定する必要はありません。

```bash
uv run python generate_voiceover.py --input presentation-20260927/slide.md
```

| 任意の指定 | 動作 |
|---|---|
| `--output-dir /path/to/audio` | 自動決定より優先する出力先 |
| `--expected-slides 20` | 指定したときだけ全体の枚数を照合。省略時に88枚を要求しません |
| `--start-slide 6 --end-slide 8` | 1始まり・両端を含む範囲。省略時は先頭／末尾。`slide_06.mp3`〜`slide_08.mp3` を生成 |
| `--voice ja-JP-NanamiNeural` | 従来と同じ音声の指定（この値が既定） |

100枚以上も元の番号を使い、99枚目は `slide_99.mp3`、100枚目は `slide_100.mp3` です。選択範囲外の音声や余分な既存ファイルは削除しません。

## 対応するMarkdownと検証

- UTF-8（BOMあり／なし）、LF／CRLF、末尾改行あり／なしに対応します。
- 先頭のYAMLフロントマターは任意です。`---` で始め、単独行の `---` または `...` で閉じます。設定内容は音声生成に使用しません。
- スライド区切りは行頭からの単独行 `---`（後続の空白・タブは可）です。コードフェンス（バッククォート／チルダ）、HTMLコメント、ノート内の `---` は区切りません。別の区切り記法や縦方向スライドは対象外です。
- 各スライドに一つの `<aside class="notes">` と `</aside>` が必要です。属性の順序、引用符、追加クラスは変更できます。コードフェンス・HTMLコメント内のasideは数えません。
- ノートはプレーンテキストです。内部のHTMLタグ・コメントはエラーにします。空白や改行は従来どおり一つの空白にまとめ、本文の文字列はそのまま渡します。
- ノートの欠落・空欄・重複・閉じタグ不備はスライド番号付きで停止します。部分生成でも全スライドを先に検証し、範囲逆転・範囲外・指定時の枚数不一致も生成前に停止します。空スライドを無視して番号を詰めることはありません。

## 失敗・中断時の動作

同じ出力フォルダーの一時ファイルへ生成し、サービスが正常終了して内容が空でないことを確認してからMP3を置換します。失敗・Ctrl+Cなどによる中断時は、そのスライドの既存MP3を保持し、一時ファイルを削除します。完了済みの番号と失敗・中断した番号を表示し、以降の生成を止めます。完了済みのMP3は保持されるため、再実行時に範囲を指定できます。OSによる強制終了・電源断では一時ファイルの自動削除は保証されません。

生成時にはedge-ttsが外部音声サービスへ接続します。Makefileのuvの `--offline` は依存関係取得を制限する指定で、音声サービスへの接続を止めるものではありません。
今回の汎用化作業ではdry-runとテスト用代替による検証だけを行い、実サービスへの通信・MP3再生成は行っていません。汎用テストだけを実行する場合は `make -C presentation-20260927 check-voiceover` を使います。
